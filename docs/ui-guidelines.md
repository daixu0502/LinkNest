# 管理界面说明规范

所有管理页面沿用以下分类，不按页面各自选择提示框样式：

| 内容 | 组件与表现 | 是否可隐藏 |
| --- | --- | --- |
| 辅助提示、使用建议 | `notice(text)`，统一浅色提示条 | 本次隐藏 / 不再提示；设置中可恢复 |
| 功能说明、字段解释 | `functionNote(text)` 或字段下方说明，直接融入布局 | 否，不增加独立卡片或提示框 |
| 普通运行状态、最近操作结果 | `statusNote(text)`、状态标签，直接融入所属区域 | 否，不受历史提示隐藏设置影响 |
| 重要操作确认、授权后果 | `actionNote(text)`，独立边线确认区域 | 否，主要放在操作确认弹窗中 |
| 实际故障、安全警告、未同步风险 | `actionNote(text, true)`，统一警告区域 | 否，错误不得受帮助开关影响 |

弹窗不能使用可关闭的 `notice`，避免用户隐藏说明后看不到操作影响。普通说明也不应仅为了不可隐藏而改用 `actionNote`。

多段说明与开关组成的区域使用 `content-stack` 统一纵向间距。说明文字允许换行，开关不收缩；不要通过负边距或固定高度压缩文字。状态区域应保留已有结果，刷新中不清空内容。

## 按钮与导航入口反馈

按钮、`summary` 和按钮式导航链接共用 `web/button-feedback.css`。新增可点击卡片或列表入口时，为实际带 `href` 的链接添加 `control-link`，不要为页面单独编写旧式深色悬停背景。普通正文链接、公共轻面板站点卡片保留各自语义和交互，不套用按钮背景。

悬停（精细指针）、键盘 `:focus-visible` 与按下反馈使用统一主题变量；焦点轮廓内收，不改变控件尺寸或裁切圆角。禁用控件不显示可操作反馈；状态标签的成功、警告、错误颜色不随父入口高亮改变。选项卡的滑动选中指示器、危险按钮配色属于有意保留的组件差异。

总览的网络服务、证书有效期和域名同步行共用同一套布局规则：桌面列表四周留白 `14px`、行内边距 `13px 12px`、圆角 `12px`、四边预留 `1px` 透明边框；手机端共用 `8px` 列表留白与 `12px 8px` 行内边距。悬停时显示完整闭合描边，不能保留零左右内边距、仅底边分隔线或最后一行取消边框的旧规则。验收需直接比较参考行与目标行的内外留白、圆角、四边宽度和状态描边，并覆盖单条及多条数据，不能只检查颜色。

本地回归：`node scripts/test-interaction.mjs`；`node scripts/test-button-feedback.cjs` 使用本机 Edge 或 WSL 测试容器内的 Chromium、静态源码及模拟 API，检查深浅主题和桌面 / 窄窗口 / 手机下的悬停、键盘焦点、按下、禁用、高对比度与减少动态效果，不连接生产服务。

修改后至少检查桌面、窄窗口、手机三种宽度；检查长地址、时间戳、警告、开关、操作按钮同时出现时无重叠或横向溢出。运行 `node scripts/test-notices.mjs` 与可选的 `node scripts/test-dialog-layout.cjs`。
